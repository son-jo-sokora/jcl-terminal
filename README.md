# JCL 練習端末

ブラウザだけで動く、z/OS 風の JCL 練習用シミュレータです。
ISPF に似た画面で JCL を書いて `SUB` で投入すると、JES2 のメッセージが返ってきます。ジョブの出力は SDSF に似た画面で確認できます。

### ▶ 今すぐ試す: https://son-jo-sokora.github.io/jcl-terminal/

上のリンクを開くだけで使えます。ダウンロードやインストールは要りません。

- **インストール不要**です。ファイルは `index.html` の1つだけで、ブラウザで開けば動きます。
- メインフレームの実機やアカウントは要りません。
- 書き間違えると、実機に近い JCL エラーメッセージ（`IEFC605I` など）が返ります。間違え方の練習にも使えます。
- **[MVS コンソール シミュレータ（mvs-console-sim）](https://son-jo-sokora.github.io/mvs-console-sim/)と連携できます。** この端末で投入したジョブを、別のタブのシミュレータ（オペレーター側）の JES2 が実行します。データセットの奪い合い、ジョブからの問い合わせ、保留ジョブ、再起動をまたぐジョブなど、利用者とオペレーターが関わる場面を体験できます（[6. 連携モード](#6-mvs-コンソール-シミュレータとの連携モード)）。

> [!IMPORTANT]
> これは本物の z/OS ではなく、学習用のシミュレーションです。メッセージの番号や文面は z/OS 3.2 のマニュアルと照合していますが、実機と異なる場合があります。`JCK` で始まるメッセージと、キーワードの重複を知らせる `IEFC633I`（末尾に `SIMULATOR MESSAGE` と表示）は、この練習端末独自のもので、実際の z/OS にはありません。業務や試験の正解として扱わず、実機の動作は IBM のマニュアルで確認してください。

```
 EDIT       USER01.JCL(HELLO) - 01.00                     Columns 00001 00072
Command ===> SUB                                              Scroll ===> CSR
****** ***************************** Top of Data ******************************
000100 //HELLO    JOB (ACCT),'USER01',CLASS=A,MSGCLASS=X,
000200 //             MSGLEVEL=(1,1),NOTIFY=&SYSUID
000300 //STEP1    EXEC PGM=IEBGENER
  ...

IKJ56250I JOB HELLO(JOB01234) SUBMITTED
***
17.18.43 JOB01234 $HASP165 HELLO    ENDED AT N1  MAXCC=0000 CN(INTERNAL)
***
```

## 1. 自分の PC で試す

必要なのは、新しめのブラウザ（Chrome、Edge、Firefox、Safari）だけです。

**とりあえず触ってみたいだけなら、[公開ページ](https://son-jo-sokora.github.io/jcl-terminal/) を開けば十分です。** 自分の PC に置いて使いたい人や、改造したい人は、次の3つの方法から選んでください。

### 方法 A: ZIP をダウンロードして開く（いちばん簡単）

Git を使ったことがない人向けです。

1. このページの上にある緑色の **「Code」** ボタンを押します。
2. **「Download ZIP」** を選びます。
3. ダウンロードした ZIP ファイルを展開（解凍）します。
   - Windows: ZIP を右クリック →「すべて展開」
   - Mac: ZIP をダブルクリック
4. 展開してできたフォルダの中の **`index.html` をダブルクリック**します。ブラウザで画面が開けば準備完了です。

> [!TIP]
> ダブルクリックで別のアプリ（メモ帳など）が開いてしまう場合は、`index.html` を右クリックして「プログラムから開く」→ ブラウザを選んでください。ブラウザの窓に `index.html` をドラッグ＆ドロップしても開けます。

### 方法 B: git clone する

Git を入れている人向けです。

1. このページの緑色の **「Code」** ボタンを押し、表示された URL（`https://github.com/...`）をコピーします。
2. ターミナル（Windows は PowerShell、Mac は「ターミナル」）で次を実行します。`<コピーしたURL>` はコピーした URL に置き換えてください。

   ```bash
   git clone <コピーしたURL>
   ```

3. できたフォルダの中の `index.html` をブラウザで開きます。

更新を取り込むときは、そのフォルダで `git pull` を実行します。

### 方法 C: GitHub Pages で自分専用の URL を作る

インストールせずにスマホや別の PC からも使いたい人向けです。GitHub アカウントが必要です。

1. このページ右上の **「Fork」** を押して、自分のアカウントにコピーします。
2. コピーしたリポジトリで **Settings → Pages** を開きます。
3. **「Build and deployment」** の Source で **「Deploy from a branch」** を選び、Branch で **`main`**、フォルダで **`/ (root)`** を選んで **Save** を押します。
4. 1〜2分待つと、同じ画面に `https://<あなたのユーザー名>.github.io/<リポジトリ名>/` という URL が表示されます。そこを開けば使えます。

### (任意) ローカルサーバーで開く

通常は不要です。ブラウザの設定で `file://` のページが制限されている場合だけ使ってください。Python が入っていれば、`index.html` のあるフォルダで次を実行します。

```bash
python -m http.server 8000
```

その後、ブラウザで `http://localhost:8000` を開きます。止めるときはターミナルで `Ctrl+C` を押します。

## 2. 最初の5分

開くと、`HELLO` という JCL の編集画面が表示されます。

1. 画面上部の **`Command ===>`** に `SUB` と入力して **Enter** を押します。
2. 次のようなメッセージが出ます。`$HASP165 ... MAXCC=0000` は「ジョブが正常に終わった」という意味です。

   ```
   IKJ56250I JOB HELLO(JOB01234) SUBMITTED
   17.18.43 JOB01234 $HASP165 HELLO    ENDED AT N1  MAXCC=0000 CN(INTERNAL)
   ```

3. **Enter** で編集画面に戻ります。
4. `Command ===>` に `=SD` と入力して Enter、続けて `ST` と入力して Enter を押します。ジョブの一覧（SDSF）が開きます。
5. `HELLO` の行の左端の入力欄に `?` と入力して Enter を押すと、出力の一覧（JESMSGLG、JESJCL、JESYSMSG、SYSUT2 など）が出ます。
6. 見たい行の左に `S` と入力して Enter を押すと、中身が表示されます。**F3**（または **Esc**）で前の画面に戻ります。

次は、わざと間違えてみましょう。右側のガイドから **SYNTAX** を開き、`Command ===>` に `JCK` と入力して Enter を押します。投入しなくても、どの行がどう間違っているかが表示されます。

もっと詳しい手順は [docs/tutorial.md](docs/tutorial.md) を見てください。

## 3. キー操作

| キー | 動作 |
|---|---|
| **Enter** | コマンドを実行する（編集エリアの中でも実行。改行はしません） |
| **Shift+Enter** | 次の行の先頭の入力欄へ移る（3270 の改行キー） |
| **Tab** / **Shift+Tab** | 次 / 前の入力欄へ移る |
| **Home** | コマンド行へ移る |
| **矢印キー** | 画面上の同じ桁を保ったまま上下左右に移る |
| **Insert** | 上書きと挿入を切り替える（はじめは上書き。挿入中は画面下の行に `^`） |
| **Ctrl+Delete** | カーソルから入力欄の終わりまで消す（Erase EOF） |
| **F3** または **Esc** | 前の画面に戻る（編集中なら保存して戻る） |
| **F12** | 保存せずに戻る（SDSF では前のコマンドを呼び出す） |
| **F7 / F8** または **PageUp / PageDown** | 上下にスクロールする。量は `Scroll ===>` 欄（`CSR` / `PAGE` / `HALF` / 数字） |
| **F5 / F6** | FIND / CHANGE を繰り返す |
| **F10 / F11** | 左右にスクロールする（編集画面では 73〜80 桁を表示） |
| 画面下のボタン | タッチ操作用の Enter / F3 / F7 / F8 / F12 |

ブラウザによっては F3 が「ページ内検索」になります。その場合は **Esc** を使ってください。

よく使うコマンドは次のとおりです。

| どこで | コマンド | 意味 |
|---|---|---|
| どこでも | `=2` / `=3` / `=3.2` / `=3.4` / `=3.17` / `=SD` | 編集 / ユーティリティ選択 / データセットの作成・名前変更・削除 / データセット一覧 / z/OS UNIX ファイル一覧 / SDSF |
| 3.2 の Option | `A` / `R` / `D` / 空欄 | 新規作成（Allocate New Data Set 画面へ） / 名前変更 / 削除 / 情報表示。名前を `'` で囲まないと `USER01.` が付く |
| メンバー一覧 | `S 名前` | メンバーを開く。ない名前なら新しいメンバーを作る（何も書かずに戻ると作られない） |
| 編集画面 | `SUB` | ジョブを投入する |
| 編集画面 | `JCK` | 投入せずに JCL をチェックする |
| 編集画面 | `SAVE` / `CAN` / `CAPS ON` / `CAPS OFF` / `RESET` | 保存 / 保存せず戻る / 大文字変換の切り替え / 印やメッセージ行の消去 |
| 編集画面 | `F 文字列 [ALL]` / `C 旧 新 [ALL]` / `L 行番号` / `TOP` / `BOT` | 検索 / 置換 / 指定行へ移動 / 先頭へ / 末尾へ |
| 編集画面の行番号欄 | `I` / `D` / `R` / `C`・`M` と `A`・`B` | 挿入 / 削除 / 複製 / コピー・移動とその行き先。`DD` `RR` `CC` `MM` は2つで範囲指定 |
| SDSF ST の行 | `?` / `S` / `H` / `A` / `C` / `P` | 出力一覧 / 表示 / 保留 / 保留を解放 / 取り消し / 削除 |
| SDSF のコマンド行 | `/D T` / `/D A,L` / `/D IPLINFO` / `/D U,DASD,ONLINE` | MVS コマンド。応答は画面に重ねて表示され、`ULOG` に残る |
| SDSF のコマンド行 | `/$DJ'名前'` / `/$HJ` / `/$AJ` / `/$CJ` / `/$PJ` / `/$DI` / `/$DSPL` | JES2 コマンド（ジョブの表示・保留・解放・取り消し・削除、イニシエーター、スプール） |
| SDSF のコマンド行 | `/D R,L` / `/R nn,YES` / `/C ジョブ名` | 応答待ちメッセージ（WTOR）の一覧 / 応答 / 実行中ジョブの取り消し |
| SDSF のコマンド行 | `ULOG` / `LOG` | 自分が出したコマンドと応答 / システムログ |
| データセット一覧の行 | `E` / `B` / `D` | 編集 / 表示 / 削除 |

## 4. サンプル JCL

`USER01.JCL` に練習用のメンバーが入っています。画面右のガイドの「開く」ボタンからも開けます。

| 種類 | メンバー |
|---|---|
| 基本 | `HELLO`（IEBGENER）、`ALLOC`（データセット作成）、`SORT`（DFSORT）、`IFTEST`（IF/THEN/ELSE）、`CLEANUP`（IDCAMS） |
| エラー体験 | `BADJCL`、`SYNTAX`（よくある間違い12種類）、`ABEND`（S806）、`OPENERR`（S013-20）、`PROCERR` |
| プロシージャ | `PROCJOB`（カタログ式・オーバーライド・INCLUDE）、`INSTREAM`（インストリーム） |
| GDG | `GDGDEF`（最初に1回実行）、`GDGRUN`（4回実行すると古い世代が消える） |
| JES2・出力 | `JES2CTL`（/*JOBPARM など）、`OUTSTMT`（OUTPUT 文） |
| DD パラメーター | `DDPARMS`（LIKE・VOL・RETPD・DDNAME・PATH） |
| ジョブ制御 | `JOBRC`、`JOBCOND`、`RESTART`、`REGION`（S80A と IF ABENDCC）、`HOLDJOB`、`SCHED`、`EXPORT` |
| 連携モード用 | `LINKRPT`（`USER01.SALES.DATA` を DISP=OLD で使う）、`LINKASK`（オペレーターに印刷してよいか尋ねる） |

### 演習：要件から JCL を書く

右側のガイドの「演習」に、要件（仕様）だけが書かれた課題が10問あります。「始める」を押すとメンバー `EX01`〜`EX10` が開くので、要件を満たす JCL を書き、コマンド行に `GRADE`（この端末独自のコマンド）と入力するか「採点する」を押します。要件ごとに ✓ / ✗ が表示され、不合格なら最初に見るべきエラーメッセージも出ます。

| 問題 | 内容 | 主に使うもの |
|---|---|---|
| EX01〜EX02（入門） | SYSOUT への出力、データセットの作成 | IEBGENER、DISP、SPACE、DCB |
| EX03〜EX05（初級） | PDS とメンバー、並べ替え、行の抽出 | IEFBR14、DFSORT（SORT FIELDS、INCLUDE） |
| EX06〜EX08（中級） | 条件付き実行、GDG、何度流しても成功するジョブ | IF/THEN/ELSE、IDCAMS、DISP=(MOD,DELETE) |
| EX09〜EX10（上級） | インストリーム・プロシージャ、壊れた JCL の修正 | PROC/PEND と記号パラメーター、JCK |

採点は、あなたのデータセットに触れない別の環境で、毎回まっさらな状態から JCL を流して行います。EX06 と EX08 は、入力がある／ない、前回の残りがある／ないの2通りで流して両方を確かめます。ヒントと解答例もガイドにあります。

### 演習：MVS・JES2 コマンド（オペレーター）

オペレーターの仕事を練習する10問（`OP01`〜`OP10`）もあります。「始める」を押すと、問題に応じたジョブ（シナリオ）が実際に投入され、SDSF の画面が開きます。SDSF のコマンド行に `/` から始まるコマンドで状況を調べて対処し、`GRADE` か「採点する」を押します。出したコマンドとその順番（「確かめてから解放したか」など）と、ジョブの終わり方で採点します。

| 問題 | 内容 | 主に使うコマンド |
|---|---|---|
| OP01〜OP03（入門） | 時刻、稼働状況、IPL 情報、DASD、スプール、イニシエーターの確認 | `D T`、`D A,L`、`D IPLINFO`、`D U,DASD,ONLINE`、`$DSPL`、`$DI` |
| OP04〜OP05（初級） | 保留ジョブの確認と解放、問い合わせ（WTOR）に YES で応答 | `$DJ`、`$AJ`、`D R,L`、`R nn,YES` |
| OP06〜OP09（中級） | NO で断る、2つの問い合わせの答え分け、応答できないジョブの取り消し、出力の削除 | `R nn,NO`、`C ジョブ名`、`$PJ` |
| OP10（上級） | 保留・問い合わせ・テープ待ちが重なった夜間バッチの総合対応 | すべて |

問い合わせを出すジョブは、この端末独自の練習用プログラム `PGM=OPRASK` を使います（IBM の製品ではありません）。`PARM` の文で YES/NO を尋ね、YES なら RC 0、NO なら RC 4、取り消されると S222 で終わります。YES/NO 以外の応答には OPR003I を出して、もう一度尋ねます。自分の JCL で使うこともできます。

オペレーター演習は、この端末の中だけで完結する練習です。[連携モード](#6-mvs-コンソール-シミュレータとの連携モード)の間は使えません。IPL や停止も含めたオペレーターの練習は、MVS コンソール シミュレータの演習で行えます。

## 5. できること・できないこと

**JCL の文**
JOB、EXEC、DD、SET、IF/THEN/ELSE/ENDIF、PROC/PEND、JCLLIB、INCLUDE、OUTPUT、EXPORT、SCHEDULE、JES2 制御文（`/*JOBPARM` `/*PRIORITY` `/*ROUTE` `/*MESSAGE` `/*NOTIFY` `/*XEQ`）

**JCL の機能**
COND（JOB と EXEC）、DISP、DD * / DATA / DUMMY / SYSOUT、記号（SET、プロシージャの記号パラメーター、`&SYSUID` などのシステム記号）、後方参照、プロシージャのオーバーライド、GDG、VOL、LIKE、DDNAME、RETPD/EXPDT、PATH（z/OS UNIX ファイル）、OUTLIM、JOBRC、RESTART、TYPRUN、REGION

**プログラム**
IEFBR14、IEBGENER、SORT（ICEMAN）、IDCAMS（DEFINE GDG、DELETE、LISTCAT、PRINT、REPRO、SET）。これ以外のプログラム名を指定すると、実機と同じく S806 で ABEND します。

**受け付けるが、書式チェックだけで動作には反映しないもの**
TIME、SPIN、FREE、CNTL/ENDCNTL、XMIT、SCHEDULE の AFTER/BEFORE、JOBGROUP。JES3 の制御文（`//*MAIN` など）は、JES2 システムと同じくコメントとして扱います。

**できないこと**
COBOL などのコンパイル、自分で作ったプログラムの実行、VSAM、TSO コマンド（IKJEFT01）、複数ユーザーでの共有、実機との接続。

**データの保存場所**
作ったデータセットやジョブは、**使っているブラウザの中（localStorage）だけ**に保存されます。サーバーには送られません。別のブラウザや別の PC とは共有されず、ブラウザの閲覧データを消すと消えます。最初の状態に戻したいときは、右側のガイドの一番下にある **「初期状態に戻す」** を2回押してください。

## 6. MVS コンソール シミュレータとの連携モード

[MVS コンソール シミュレータ（mvs-console-sim）](https://son-jo-sokora.github.io/mvs-console-sim/)は、z/OS のオペレーター操作（IPL・停止・JES2・応答）を練習する姉妹プロジェクトです。2つを別々のタブで開いてつなぐと、利用者（この端末）とオペレーター（シミュレータ）の両方の立場を1人で体験できます。どちらも単独でこれまでどおり使えます。

1. シミュレータの上にある **「連携モード」** を押し、**「jcl-terminal を開く」** を押します。または、この端末を `?link` を付けて開きます（例: https://son-jo-sokora.github.io/jcl-terminal/?link ）。
2. この端末の右上に「連携モード」と表示されます。
3. シミュレータで IPL し、JES2・VTAM・TSO を起動すると、この端末の USER01 が TSO にログオンします。
4. `SUB` したジョブは、シミュレータのコンソールに `$HASP100` で現れ、シミュレータの JES2 で実行されます。

役割は、シミュレータが JES2（ジョブをいつ動かすか）、この端末がジョブの中身と結果です。

| 起きること | この端末（利用者） | シミュレータ（オペレーター） |
|---|---|---|
| TSO が止まっている | ジョブを投入できない（NOT LOGGED ON） | `S TSO` で起動する |
| `$S` の前、`$P` の後、イニシエーターの休止中 | SDSF で入力待ちのまま | ジョブは入力キューで待つ |
| データセットを他のジョブが使用中（DISP=OLD など） | ジョブが終わらない | `IEF099I` で待つ。原因のジョブを取り消すと進む |
| `OPRASK` の問い合わせ | 応答で結果（RC 0 / 4）が決まる | コンソールに `OPR001A` が出て、`R nn,YES/NO` で応答する |
| `TYPRUN=HOLD` | SDSF の行コマンド H / A / C が `$HJ` / `$AJ` / `$CJ` としてシミュレータに送られる | `$DJ` で確認、`$AJ` で解放、`$CJ` で取り消し |
| 取り消し（`C jobname`） | ABEND S222 で終わる | `IEE301I` |
| 実行中にシステムリセット → ウォームスタート | ジョブは入力待ちに戻り、再実行される | `$HASP406` |
| コールドスタート | 投入したジョブと出力が消える | スプールが初期化される |
| `P TSO` | ログオフされ、投入できなくなる | `IKT010D` の利用者数に USER01 も入る |

- 連携演習用のサンプルとして `LINKRPT`（`USER01.SALES.DATA` を DISP=OLD で使う）と `LINKASK`（印刷してよいかオペレーターに尋ねる）があります。
- 連携中は、SDSF の `/` コマンドとオペレーター演習（OP01〜OP10）は使えません。オペレーターの操作はシミュレータで行います。
- 右上の「連携を切る」で、通常の動きに戻ります。
- シミュレータの[演習シナリオ](https://son-jo-sokora.github.io/mvs-console-sim/scenarios.html)のうち、連携演習 XL1〜XL4（データセット待ちの解消、ジョブの問い合わせへの応答、再起動をまたぐ保留ジョブなど）と複合演習 C1〜C3 は、この端末と一緒に使います。利用者役の操作（`SUB`）はこの端末で行います。

> [!NOTE]
> 2つのタブが同じサイト（同じオリジン）にあるときだけつながります。公開ページ（`son-jo-sokora.github.io`）同士ならそのまま使えます。手元で使う場合は、2つのフォルダを同じ親フォルダに置き、その親フォルダでローカルサーバーを起動して（`python -m http.server 8000`）、`http://localhost:8000/mvs-console-sim/` を開いてください。ファイルをダブルクリックで開いた場合はつながりません。

## 7. うまく動かないとき

**画面が真っ白で、何も表示されない**
- ブラウザを最新版にしてください。Internet Explorer では動きません。
- `index.html` をメモ帳などで開いていないか確認してください。ブラウザで開く必要があります。
- それでもだめなら、[1. の「ローカルサーバーで開く」](#任意-ローカルサーバーで開く) を試してください。

**フォントが端末らしく見えない**
フォントはインターネット経由（Google Fonts）で読み込みます。オフラインのときは PC にある等幅フォントで表示されますが、動作は変わりません。

**F3 を押すと検索窓が出る**
ブラウザの機能と重なっています。**Esc** か、画面下の **「F3 戻る」** ボタンを使ってください。

**入力した小文字が大文字になる**
ISPF の CAPS ON と同じ動作です。小文字を使いたいときは、`Command ===>` に `CAPS OFF` と入力します。JCL のキーワードは大文字で書く必要があるので、小文字にすると JCL エラーになります。

**前に作ったデータが残っていて、サンプルどおりにならない**
たとえば ALLOC を2回投入すると、2回目は「データセットがすでにある」というエラーになります。これは実機と同じ動作です。最初からやり直したいときは、ガイドの **「初期状態に戻す」** を2回押してください。

**スマホで文字が小さい**
画面は横80桁の端末を再現しているため、幅の狭い画面では小さくなります。横向きにするか、PC で使ってください。

## 8. 改造してみる

プログラムは `index.html` の1ファイルにまとまっています。テキストエディタ（VS Code など）で開いて書き換え、ブラウザを再読み込み（F5）すると反映されます。ビルドや npm は要りません。

- **サンプル JCL を追加する**: `const SAMPLES={` の中に、`名前:[ "1行目", "2行目", ... ]` の形で追加します。再読み込みすると、新しいサンプルが `USER01.JCL` に自動で追加されます。保存済みのデータは消えません。
- **プログラム（PGM=）を追加する**: `const PROGRAMS={` の中に関数を追加します。書き方は [docs/how-it-works.md](docs/how-it-works.md) を見てください。
- **エラーのテストを流す**: GitHub Pages の `tests/run.html`（またはローカルサーバー上の同じファイル）を開くと、JCL エラーのテスト（約140件）と演習の解答例の確認を一度に実行して、成功・失敗を一覧にします。テストは保存データに触れません。テストの中身は [tests/cases.js](tests/cases.js)、マニュアル上の全エラーとの対応は [docs/error-catalog.md](docs/error-catalog.md) にあります。
- **エラー一覧を作り直す**: [docs/error-catalog.md](docs/error-catalog.md) は `tools/make_catalog.py` で作ります。マニュアルの PDF をテキストにしたファイルのフォルダを環境変数 `ZOS_TEXT_DIR` で渡します。マニュアルの文章は IBM の著作物なので、一覧にはメッセージ ID と出典のページだけを載せ、文面や説明は写しません。
- **連携部分を変えたとき**: 連携のやり取り（`LINK` モジュール、`BroadcastChannel('mvs-link-v1')`）は、MVS コンソール シミュレータ側の結合テスト [`tests/link-e2e.html`](https://son-jo-sokora.github.io/mvs-console-sim/tests/link-e2e.html) で、この端末を実際に動かして確かめています。メッセージの形や `LINKRPT` / `LINKASK` を変えたら、そちらも流してください。
